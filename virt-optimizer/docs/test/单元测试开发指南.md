# 单元测试开发指南

> **VSOCK 前置要求：** 运行 UT 前，必须确保测试环境能够创建 VSOCK 套接字。使用容器时，应在 Docker 宿主机（Docker 位于虚拟机中时即该虚拟机）加载 VSOCK 内核模块；镜像本身无法提供宿主机缺少的内核能力。否则客户端 VSOCK 相关用例将无法通过。具体检查方法见下文。

本文介绍 `virt-optimizer` 单元测试的开发要求，以及以下两种运行方式：

* 方式一：在物理机中直接运行 UT
* 方式二：在预编译容器中运行 UT

## 1. 前置动作

### 1.1 环境依赖

|环境项目|版本信息|
|:----|:----|
|推荐操作系统|openEuler 24.03 LTS SP4|
|CPU架构|支持 `x86_64` 和 `aarch64`|
|用户权限|安装与管理需 `root` 权限|
|内存|建议至少 16 GiB；内存不足可能导致编译器进程被系统终止|
|软件要求|<ul><li>CMake ≥ 3.22.0</li><li>googletest ≥ 1.10.0</li><li>rapidjson ≥ 1.1.0</li><li>clang ≥ 12.0.1</li><li>libbpf-devel ≥ 0.8.1</li><li>bpftool ≥ 7.2.0</li></ul>|

> 覆盖率报告为可选能力。openEuler 24.03 LTS SP4 默认软件源不提供 `lcov` 软件包。若环境中已有 `lcov` 和 `genhtml` 命令，`run_ut.sh` 会生成覆盖率报告；否则脚本会跳过报告生成，不影响单元测试执行。

### 1.2 拉取工程文件

拉取 `ubs-virt`，进入 `virt-optimizer` 目录：

```bash
git clone https://gitcode.com/openeuler/ubs-virt.git
cd ubs-virt/virt-optimizer
```

### 1.3 进行 UT 开发

新增 UT 代码，并上传至环境中的 `virt-optimizer/ebpf/tests/` 目录下。

如果工程文件来自 Windows，先在 `virt-optimizer` 目录转换文本文件的换行符：

```bash
find . -type f -not -path '*/\.*' -exec grep -Il '.' {} \; | xargs -d '\n' -L 1 dos2unix -k
```

Linux 环境直接获取的源码可以跳过此步骤。

## 2. 方式一：在物理机中运行 UT

### 2.1 使用限制

直接运行 UT 时，构建过程按照以下顺序查找内核类型头文件：

1. `virt-optimizer/ebpf/src/client/bpfs/vmlinux.h`
2. `/usr/include/vmlinux.h`
3. 从 `/sys/kernel/btf/vmlinux` 生成

如果前两个位置都没有预置的 `vmlinux.h`，当前运行内核必须提供 `/sys/kernel/btf/vmlinux`，并且 `bpftool` 必须能够读取它。

客户端 UT 包含 VSOCK 套接字测试。运行 UT 的物理机内核必须支持 VSOCK，并加载 VSOCK 模块。

### 2.2 检查内核类型头文件

执行：

```bash
if test -s ebpf/src/client/bpfs/vmlinux.h; then
    echo "使用工程内预置的 vmlinux.h"
elif test -s /usr/include/vmlinux.h; then
    echo "使用系统预置的 /usr/include/vmlinux.h"
elif test -r /sys/kernel/btf/vmlinux; then
    bpftool btf dump file /sys/kernel/btf/vmlinux format c >/dev/null
    echo "使用当前内核 BTF 生成 vmlinux.h"
else
    echo "未找到可用的 vmlinux.h 或内核 BTF"
    exit 1
fi
```

### 2.3 检查 VSOCK

加载基础 VSOCK 模块：

```bash
modprobe vsock
```

检查模块及套接字创建能力：

```bash
lsmod | grep -E '(^|_)vsock|virtio.*vsock'

python3 - <<'PY'
import os
import socket

try:
    sock = socket.socket(socket.AF_VSOCK, socket.SOCK_STREAM, 0)
    print("VSOCK_CREATE=SUCCESS")
    sock.close()
except OSError as exc:
    print(f"VSOCK_CREATE=FAILED errno={exc.errno}: {os.strerror(exc.errno)}")
    raise SystemExit(1)
PY
```

只有输出 `VSOCK_CREATE=SUCCESS` 后，才继续运行 UT。

### 2.4 编译并运行 UT

进入 `virt-optimizer` 目录，执行以下命令，完成基本的 Debug 包编译：

```bash
bash build.sh -t debug
```

进入 `virt-optimizer/ebpf/` 目录运行 UT：

```bash
cd ebpf
bash run_ut.sh
```

`run_ut.sh` 也会调用 `build.sh -t debug`，以确保 UT 对应当前源码。

## 3. 方式二：在预编译容器中运行 UT

### 3.1 使用限制

预编译镜像提供 UT 所需的用户态软件依赖和 `/usr/include/vmlinux.h`。因此，编译和 UT 不要求 Docker 宿主机存在 `/sys/kernel/btf/vmlinux`。

容器与 Docker 宿主机共享 Linux 内核，镜像不能提供或加载宿主机缺少的内核模块。客户端 UT 包含 VSOCK 套接字测试，因此启动容器前必须在 Docker 宿主机确认 VSOCK 可用。若 Docker 运行在虚拟机中，此处的“宿主机”指该虚拟机。

### 3.2 在 Docker 宿主机准备 VSOCK

执行：

```bash
sudo modprobe vsock

# Docker 运行在 KVM 虚拟机中时执行
sudo modprobe vmw_vsock_virtio_transport

lsmod | grep -E '(^|_)vsock|virtio.*vsock'
```

如果模块加载失败，检查当前内核配置和模块文件：

```bash
grep -E 'CONFIG_VSOCKETS|CONFIG_VIRTIO_VSOCKETS' \
    /boot/config-$(uname -r) 2>/dev/null
find /lib/modules/$(uname -r) -type f -iname '*vsock*'
```

### 3.3 拉取并启动容器

该镜像允许匿名拉取，执行：

```bash
docker pull swr.cn-north-4.myhuaweicloud.com/ubscore/ubs-virt:oe2403-v1
```

> 若返回 `denied` 或 `unauthorized`，请向镜像仓库管理员申请读取权限后重试。

启动容器：

```bash
docker run -it \
    --name=ubs-virt \
    swr.cn-north-4.myhuaweicloud.com/ubscore/ubs-virt:oe2403-v1 \
    /bin/bash
```

仅运行构建和 UT 时，不需要将宿主机的 `/lib/modules` 或 `/sys/kernel/btf/vmlinux` 挂载到容器，也不需要授予容器加载内核模块的权限。

### 3.4 在容器中检查环境

进入容器后，检查预置头文件：

```bash
test -s /usr/include/vmlinux.h
sha256sum /usr/include/vmlinux.h
```

检查容器能否使用宿主机提供的 VSOCK：

```bash
python3 - <<'PY'
import os
import socket

try:
    sock = socket.socket(socket.AF_VSOCK, socket.SOCK_STREAM, 0)
    print("VSOCK_CREATE=SUCCESS")
    sock.close()
except OSError as exc:
    print(f"VSOCK_CREATE=FAILED errno={exc.errno}: {os.strerror(exc.errno)}")
    raise SystemExit(1)
PY
```

常见失败含义：

* `errno=97`（`Address family not supported by protocol`）：Docker 宿主机未提供或未加载 VSOCK。
* `errno=1`（`Operation not permitted`）：需要检查容器的 seccomp 等安全策略。

以上检查只验证 UT 所需的套接字创建能力。实际进行宿主机与虚拟机之间的 VSOCK 通信时，还需要由虚拟化平台为虚拟机配置 virtio-vsock 设备和 CID。

### 3.5 在容器中运行 UT

拉取源码并进入 `virt-optimizer`：

```bash
cd /home
git clone https://gitcode.com/openeuler/ubs-virt.git
cd ubs-virt/virt-optimizer
```

进入 `virt-optimizer/ebpf/` 目录运行 UT：

```bash
cd ebpf
bash run_ut.sh
```

`run_ut.sh` 会完成 Debug 构建并运行全部 UT，无需在容器中提前单独执行 `bash build.sh -t debug`。

## 4. 结果判断和常见问题

脚本退出码为 `0`，并且以下四个测试程序均无失败用例，表示 UT 通过：

```text
build/debug/tests/client/test-client
build/debug/tests/common/test-common
build/debug/tests/server/test-server
build/debug/tests/optimizer/test-optimizer
```

日志中的配置解析失败等错误信息可能来自异常路径测试，应以 GoogleTest 汇总结果和脚本退出码为准。

若缺少 `lcov` 或 `genhtml`，日志会显示：

```text
Skipping coverage report generation.
```

这表示脚本跳过覆盖率报告，不表示 UT 失败。

若构建阶段出现以下错误：

```text
c++: fatal error: Killed signal terminated program cc1plus
```

表示可用内存不足。应增加环境内存；也可以降低并行度后重新运行：

```bash
export CMAKE_BUILD_PARALLEL_LEVEL=1
bash run_ut.sh
```
